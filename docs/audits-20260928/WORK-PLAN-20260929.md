## T1-10 evidence — fail-closed native-binary preflight (2026-09-29)

**Gap found:** the version/binary check in `herdr-agent-verify-startup` was
hard-gated to one harness — `verify_agy_cli_version()` begins
`[ "$kind" = agy ] || return 0` (line 634). Every other kind (pi, codex, claude,
omp, senpi) had **no native-binary check at all**, and there were **zero** size
guards anywhere in the 735-line script. That is exactly the hole the
2026-09-24 hollow-package incident fell through.

**RED:** `grep -cE "1024|1KB|too small|hollow|size"` → `0`. A 0-byte and a
17-byte "CLI" were both undetectable by any existing logic.

**GREEN:** added `verify_native_binary()`, called in `main()` for **every** kind,
immediately before `verify_agy_cli_version()`. It resolves the binary through
PATH (never a bare `$0`), follows it with `readlink -f`, and requires:
exists, is executable, and is **>= 1024 bytes**. Any miss → `rc=79` with a
specific reason (`NATIVE_BINARY_MISSING` / `NATIVE_BINARY_NOT_EXECUTABLE` /
`NATIVE_BINARY_HOLLOW`).

| Case | Expected | Result |
|---|---|---|
| 0-byte hollow `agy` | refuse | `NATIVE_BINARY_HOLLOW … only 0 bytes` → rc=79 |
| 17-byte broken `pi` | refuse | `NATIVE_BINARY_HOLLOW … only 17 bytes` → rc=79 |
| 4096-byte `senpi` | pass | rc=0 |
| real `/root/.local/bin/agy` | pass | rc=0 |

**Regression:** existing suite = **37/39 passed, 2 failed**. The same 2 failures
reproduce against the pre-change backup, so they are a **pre-existing baseline,
not a regression**. One of them is the test suite's own `agent-secret-scan`
invocation, which surfaces the known-accepted 2-file baseline (the two
`.minimax/v2/sessions/**` transcripts holding the operator-acknowledged elevates
token) — not caused by this change. Backup:
`herdr-agent-verify-startup.bak-20260929T071853Z`.

## T1-11 evidence — fleet-hygiene postinstall gate (2026-09-29)

**Gap found:** `grep -cE "1024|sha256|POSTINSTALL|hollow"` → `0`. Post-update
verification was `$vcmd` (i.e. `--version`) exit code only.

**RED:** a **67-byte** stub script whose `--version` prints `1.0.0` passes
today's verify with **rc=0**. A hollow refresh could therefore be recorded as
`UPDATED-PASS` over a broken CLI — precisely the 2026-09-24 failure.

**GREEN:** added `postinstall_guard()` (exists, executable, >= 1024 B) layered
**in front of** the original `--version` check, which is preserved exactly — both
must pass. On success it writes `postinstall.sha256` into the snapshot dir and
logs size + digest prefix. Failures roll back via the existing `restore` path.

| Case | Before | After |
|---|---|---|
| 67-byte stub answering `1.0.0` | rc=0 (UPDATED-PASS) | `POSTINSTALL-HOLLOW … only 67B` → rc=1 → rollback |
| `fleet-hygiene inventory` | works | works (pi/senpi/omp/claude all listed) |

**Honest note — regression caught and fixed mid-flight:** the first edit
replaced the `--version` check instead of layering in front of it, which would
have *weakened* the existing contract. Corrected before merge; both checks now
run. This is recorded rather than hidden because it is exactly the kind of
silent weakening TDD is meant to catch.
