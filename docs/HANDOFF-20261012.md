and ~109) but has **no launch template in `bin/fm-spawn.sh`**. So:

```
$ bin/fm-spawn.sh <id> <home> --harness minimax-code --model minimax/MiniMax-M3.1-Flash-Preview
error: unknown harness 'minimax-code'; pass a raw launch command to use an unverified adapter
```

Two edits fix it:

1. `launch_template()` at **`bin/fm-spawn.sh:457`** — its `case` covers `claude`, `codex`,
   `opencode`, `pi|pi-signed`, `grok`, `kimi`, `agy`. Add `minimax-code`. mcode takes the
   prompt as a **positional argument** (`mcode [options] [prompt]`), not a flag.

   `--model` is not silently dropped. mcode accepts `-m, --model <provider/model>`, so the
   shared `--model %s` form is valid.

Use the existing placeholders (`__MODELFLAG__`, `__OPINPUT__`, `__BRIEF__`). Do not
restructure anything else — `fm-spawn.sh` is the most load-bearing file in the fleet.

A brief for this already exists at `data/minimax-code-launch-template-20261012/brief.md`
with all the verified mcode CLI facts. A crew was dispatched for it but went idle with no
