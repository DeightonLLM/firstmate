## What the bug was, so the test has a reason to exist
On 2026-10-15 a single watcher cycle emitted TWO check wakes. Firstmate drained once, acted on the wake it
read, and silently discarded the other. A Controller message went unread until the Captain prompted it. He
called it a broken loop and he was correct.

The owning protocol `docs/supervision-protocols/pi.md` step 1 now requires draining UNTIL the drain prints
nothing, and acting on every record it names. This test must prove that contract mechanically so it cannot
regress silently again.

## What the test must prove
1. `fm-wake-drain.sh` on an empty queue prints NOTHING and exits 0. A drain that always prints something
   would make a naive loop spin forever.
2. With queued wakes present, a drain prints them AND removes them, so a second drain prints nothing. That is
   the convergence property the loop depends on.
3. A loop that drains repeatedly terminates rather than spinning forever. Run it under a wall-clock bound and
   fail if it does not converge.
4. The protocol text at `docs/supervision-protocols/pi.md` actually states the loop requirement. If someone
   removes the wording, the test fails. Documentation that can silently regress is not documentation.
