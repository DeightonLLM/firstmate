## Per-domain observations

### core-distro.com

- **Apex + www:** `https://core-distro.com/` and `https://www.core-distro.com/` each returned HTTP 200 and rendered the same Core Distro pharmaceutical supply distribution homepage; each remained on its requested host (no loop/redirect). Navigation includes products, about, compliance, contact, resources, blog and FAQ. Desktop H1: “VIALS. STOPPERS. SEALS. DONE. ONE PARTNER.”
- **Forms:** one newsletter form, email required, optional name, “Subscribe”; React handler calls `g.mutate({email, name, source})` (measured in public page JS at `/_next/static/chunks/app/page-ef5316425ebc539f.js`). That is a real online submission, so it was not submitted; it may create a subscription/contact record. Contact/quote navigation leads to `/contact/`; not submitted.
- **Chat:** visible floating chat widget on mobile. Opening it produced “Send a chat to get started”, “Send message”, “Powered by HD2.ai”, “Reset Chat”; open panel measured 366×820 at x=12,y=12 on 390×844. Focus landed in `textarea#message-input`. Keyboard Tab sequence proceeded through Send message, Powered by link, Reset Chat and then to page controls: **no focus trap reproduced**. Sending would submit a chat message and was not attempted.
- **Mobile:** 390px viewport, document width 390px, no horizontal overflow; chat panel fits with 12px margins. Widget overlaps page content by design while open, but remained inside viewport.
- **Images/headings:** with image requests blocked, page text and headings remained; seven image elements, each with nonempty alt text in the observed set. One H1 followed by H2/H3 sections.
- **Highest impact:** visibly contradictory performance counters on a site making compliance/quality claims; evidence is rendered page text, not external validation of the claims.

### elevatesci.com

- **Apex + www:** both HTTPS roots returned 200, rendered the same Elevate Life Sciences research-products storefront, and stayed on requested hostname. H1 “Leading Peptide Excellence”; product cards include AOD-9604, BPC-157 and BPC-157 + TB-500, with prices. No parked/maintenance page.
- **First visit / navigation:** a viewport-filling “Research Use Confirmation” overlay is present initially; it asks the visitor to affirm age 21+ and research-only use before “Enter the catalog.” I did not accept/close it or proceed through checkout. Product navigation targets `/shop`, `/product/...`; links are present.
- **Forms:** newsletter email form is present. Public `https://elevatesci.com/js/main.js` binds submit, prevents default, hides the form and displays “Static Catalog Preview: Email updates are disabled in this export. Inquire directly at info@elevatesci.com.” This is direct source evidence that the newsletter cannot subscribe online; no form was submitted. Quote/cart/payment actions were not attempted.
- **Chat:** widget button exists in DOM; on initial mobile load the research-use gate overlays the visitor surface, so I did not try to bypass it or send chat. No trap determination made.
- **Mobile:** 390px, no horizontal overflow (document width 390px); gate fills viewport. No exposed layout overflow found. Some lazy image requests were not complete in the short wait; most images had alt text (brand-logo alts observed).
- **Images/headings:** page text and H1/H2/H3 structure remain when images are blocked. One H1, section H2s, product H3s.
- **Highest impact:** gate prevents an unconfirmed first-time visitor from accessing catalog content; likely intended restriction, but it is a material friction point. Separate functional defect: online newsletter submission is explicitly disabled.

The rendered page says “Registered at”, offers “Manage domain”, and promotes Hostinger web hosting, AI website building and VPS products. No Whoosh content, site navigation, contact, or form. Both hosts show the same parked page.

### cbd-data.com

- **Apex + www:** both returned HTTP 200 and rendered the same CBD-Data B2B lead-generation landing page, staying on requested hostname. Visible claims include search/enrichment/CSV, 12M+ leads, 99% data accuracy, 50K+ cities and pricing from $999/month; the content looked like a product marketing page, not a parked/maintenance page. A working search or lead workflow was not exercised.
- **Forms/actions:** two forms: newsletter email and signup CTA. CTA form has inline `onsubmit="event.preventDefault(); openAuthModal(this.querySelector('input').value);"`; it opens the auth modal and carries the email. Modal form asks for full name, email, password (minimum six characters), and `onsubmit="handleAuth(event)"`; public inline JS switches the button to “Creating account...” and contains signup/login handling. Completing it could create a real user record; neither form was submitted. Newsletter behavior is not established by its markup; no submission.
- **Mobile:** 390px, page width 390px with no horizontal overflow; fixed header 57px. Sign-up modal is available from CTA; no account was created. No chat widget detected.
- **Images/headings:** text remains with image requests blocked; one logo image with alt “Logo”. One H1, then H2/H3 hierarchy.
- **Highest impact:** visitors are invited into a free lead-generation trial but the action proceeds directly toward account creation; no functioning application/search experience was demonstrated without submitting potentially record-creating credentials. The visible performance/scale claims are unverified, not asserted false.

## Methods and reproducible evidence

Commands/tooling run (all GET/read-only; forms/chat not submitted):

- `google-chrome --version` → `Google Chrome 155.0.8059.39`.
- Puppeteer Core with Chrome: `page.goto('https://'+host, {waitUntil:'domcontentloaded'})` for each apex and www root; queried `location.href`, HTTP response status, title, visible text, headings, forms/input attributes, image `alt`, chat controls, and mobile `scrollWidth` at 390×844. Both aliases measured independently for all four domains. Results summarized above: all 8 root requests returned 200; Whois parked page reproduced on both Whoosh aliases; other six roots rendered the named product sites.
- Repeat browser pass with Chrome request interception aborting image resource types, then inspected `document.body.innerText`, image counts, dialog text, controls; content remained readable without image files.
- Core widget: mobile click `#anything-llm-embed-chat-button`, inspect panel and active element, then 12 sequential Tab presses. Focus moved through widget controls and back to page (`BODY`), which does not reproduce a focus trap.
- Public client-code reads: `curl -fsS --max-time 15 https://elevatesci.com/js/main.js | grep -A20 -B2 -n 'Static preview mode' | head -25` → lines 212–225 identify disabled online newsletter submission and email fallback. `curl -fsS --max-time 15 https://core-distro.com/_next/static/chunks/app/page-ef5316425ebc539f.js | grep -o '.\{0,100\}g.mutate({email:l,name:d||void 0,source:s}).\{0,100\}' | head -1` → confirms subscription mutation handler.
- Browser DOM inspection of CBD-Data form outerHTML found inline `openAuthModal(...)` and `handleAuth(event)` handlers; static inline source shows `handleAuth` retrieves email/password and switches the submit button to “Creating account...”. No request was fired.
- No customer message was sent, no account was created, no newsletter subscribed, no checkout/payment initiated, and no quote/contact form submitted.
